Сайт открытый, и любая помощь приветствуется: исправленная опечатка в эталонном запросе полезна не меньше новой задачи. То же руководство лежит в репозитории — в [CONTRIBUTING.md](https://github.com/butyavk/live-coding/blob/main/CONTRIBUTING.md) (на английском).

<Aside type="tip" title="Коротко">
- Нашли неверный ответ, сломанную проверку или опечатку? Создайте [issue](https://github.com/butyavk/live-coding/issues).
- Небольшая правка текста: ссылка «Редактировать страницу» внизу любой страницы.
- Упражнения, ловушки и задачи лежат в `src/data/practice/*.ts` и `exercises/`; после изменений запустите `npm run exercises`.
- Любое изменение вносится и в английскую, и в русскую страницу; сначала прочитайте [руководство по контенту](https://github.com/butyavk/live-coding/blob/main/CONTENT_GUIDE.md).
- Перед pull request: `npm run check:content`, `npm run build`, `npm run check:links`.
</Aside>

## Сообщить о проблеме

Создайте [issue на GitHub](https://github.com/butyavk/live-coding/issues) и укажите, где вы увидели проблему: страницу, идентификатор упражнения (например, `s-filter` или `q01`) и что вы ожидали. Полезные сообщения:

- **Неверный эталон.** Проверка проходит с неверным ответом или не проходит с верным. Приложите свой запрос или функцию.
- **Непонятный вопрос.** Текст задачи можно понять двумя способами, или в нём нет правила, на которое опирается эталон.
- **Неверное число или утверждение** в тексте страницы.
- **Проблема со средой выполнения.** Редактор не загружается или запуск не заканчивается. Укажите браузер и его версию.
- **Русский текст** читается неестественно или расходится с английской страницей.

## Запуск сайта локально

Понадобятся [Node.js](https://nodejs.org/en/download) версии 22.18 или новее, Git и Python 3 — для проверки упражнений и для заданий без сети.

<Steps>

1. Сделайте форк репозитория на GitHub и клонируйте его:

   ```bash
   git clone https://github.com/<your-username>/live-coding.git
   cd live-coding
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Запустите сервер разработки. Он скопирует среды выполнения PostgreSQL и Python в `public/runtime/`, выведет локальный адрес (по умолчанию `http://localhost:4321/live-coding/`) и будет перезагружать страницы при правках:

   ```bash
   npm run dev
   ```

4. Создайте ветку для изменений:

   ```bash
   git checkout -b fix/q05-zero-months
   ```

5. Закончив, один раз соберите весь сайт. Результат попадает в `dist/`; `npm run preview` раздаёт его локально:

   ```bash
   npm run build
   ```

</Steps>

## Как устроен контент

```text
src/content/docs/
├── index.mdx                      главная страница на английском
├── start/introduction.mdx         английские страницы: <раздел>/<slug>.mdx
├── sql/joins.mdx
├── ...
└── ru/
    ├── index.mdx                  главная страница на русском
    ├── start/introduction.mdx     русская пара: тот же раздел, то же имя файла
    └── ...
src/data/practice/                 упражнения, ловушки и задачи (данные для компонентов)
src/data/generated/practice.json   эталонные результаты, их пишет npm run exercises
src/data/skill-map.ts              карта навыков: страницы и их зависимости
src/data/study-plan.ts             три плана подготовки
exercises/                         данные в CSV, файлы задач, тесты, решения
scripts/pages.json                 все разделы и слаги в порядке бокового меню
scripts/sql.mjs                    выполняет запрос на учебных данных в PostgreSQL
scripts/check-mdx.mjs              самопроверка файлов контента
CONTENT_GUIDE.md                   правила написания страниц
```

- **Английские** страницы лежат в `src/content/docs/<раздел>/<slug>.mdx`, **русские** — в `src/content/docs/ru/<раздел>/<slug>.mdx`, с точно таким же разделом и именем файла.
- **Боковое меню** строится по папкам; `sidebar.order` во frontmatter — это место страницы в `scripts/pages.json`.
- **Новой странице** нужен слаг в `scripts/pages.json` и узел в `src/data/skill-map.ts` с её зависимостями, иначе сборка упадёт.
- **Внутренние ссылки** пишутся от корня, без локали и базового пути, и заканчиваются слешем: `/sql/joins/`. Сборка сама добавит `/live-coding` и `/ru`.

## Добавить упражнение, ловушку или задачу

Интерактивные компоненты берут данные из `src/data/practice/`, а эталонные результаты — из `src/data/generated/practice.json`. Объяснения живут в страницах MDX.

- **Упражнение по SQL.** Добавьте запись в `src/data/practice/sql-drills.ts`: идентификатор, начинающийся с `s-`, вопрос `q` по-английски — так, как его сказал бы интервьюер, — и эталонный запрос `ref`. Поставьте `ordered: true`, если порядок строк — часть ответа.
- **Упражнение по Python.** Добавьте запись в `src/data/practice/py-drills.ts`: идентификатор, начинающийся с `y-`, `q`, заготовку `starter`, эталон `ref` и тесты `tests` (вызов и ожидаемое значение или исключение, которое он выбрасывает). Эталон должен проходить все тесты, а заготовка — не проходить.
- **Ловушка.** Добавьте запись в `src/data/practice/traps.ts`: запрос `sql`, который выглядит правильно, но работает не так, и необязательное исправление `fix`. Вопрос и ответ пишутся на странице, на каждом языке.
- **Задача по SQL.** Условие, вопросы, которые стоит задать, и колонки результата — в `exercises/tasks/sql/<id>.sql`, эталон — в `exercises/solutions/sql/<id>.sql`, пояснения к данным — в `src/data/practice/sql-tasks.ts`.
- **Задача по Python.** Напишите `exercises/tasks/<file>.py` (условие — в docstring), `exercises/tests/test_<file>.py` и `exercises/solutions/<file>.py`, затем добавьте описание и пример в `src/data/practice/py-tasks.ts`.

Затем разместите новый идентификатор на одной английской и одной русской странице вместе с объяснением или разбором и пересоберите эталонные результаты:

```bash
npm run exercises
```

Команда выполняет каждый эталон SQL на PostgreSQL (PGlite), проверяет каждое упражнение по Python через `python3` и записывает `src/data/generated/practice.json`. Закоммитьте обновлённый файл. Чтобы проверить и задания без сети, прогоните эталоны через pytest:

```bash
cd exercises
SOLUTIONS=1 uv run pytest
```

## Написать страницу

[Руководство по контенту](https://github.com/butyavk/live-coding/blob/main/CONTENT_GUIDE.md) описывает шаблоны страниц, frontmatter, компоненты, стиль, англо-русский глоссарий и подводные камни MDX. Прочитайте его, прежде чем писать или переписывать страницу. Вкратце:

- **Числа — из настоящих запусков.** Каждое число и каждая таблица с выводом на странице получены запросом, который вы выполнили: `node scripts/sql.mjs "SELECT …"` печатает результат таблицей Markdown. Каждый фрагмент на Python, который вы показываете, тоже запущен.
- **Своими словами.** Не вставляйте текст из документации, книг и блогов. Давайте ссылки на официальную документацию PostgreSQL и Python в разделе «Что почитать».
- **Нейтрально.** Учебные данные — выдуманный маркетплейс подписок с выдуманными продавцами и маркетплейсами. Никаких названий реальных компаний — ни в тексте, ни в данных — и никаких имён людей.
- **Простой английский, британская орфография.** Короткие предложения и обычные слова: многие читатели — не носители языка.
- **Оба языка в одном pull request.** Русская страница сохраняет ту же структуру, заголовки, код и упражнения, но написана живым техническим русским языком. Тексты задач и фразы, которые нужно произносить, на обеих версиях остаются английскими. Пишете только на одном языке? Всё равно откройте pull request и укажите это.

## Проверка изменений

Сначала запустите проверку контента для своих файлов. Она сообщает об ошибках синтаксиса MDX, неполном frontmatter, внутренних ссылках на несуществующие страницы, отсутствующей языковой паре и идентификаторах упражнений, которых нет или которые размещены дважды:

```bash
node scripts/check-mdx.mjs src/content/docs/sql/joins.mdx src/content/docs/ru/sql/joins.mdx
```

Если на странице есть блоки SQL, выполните их все на учебных данных. Скрипт перечислит блоки, которые падают; фрагмент или намеренная ошибка падают нарочно, всё остальное должно выполняться:

```bash
node scripts/check-sql-blocks.mjs src/content/docs/sql/joins.mdx src/content/docs/ru/sql/joins.mdx
```

Затем запустите полные проверки — те же, что выполняет CI:

```bash
npm run check:content   # все страницы; заодно проверяет, что каждое упражнение размещено на обоих языках
npm run build           # собирает сайт и проверяет карту навыков и планы подготовки
npm run check:links     # каждая внутренняя ссылка и #якорь в собранном сайте
```

Исправьте все ✗, прежде чем открывать pull request.

## Чек-лист для pull request

- Изменение внесено **и** в английскую, **и** в русскую страницу, или в описании сказано, какой половины не хватает.
- Frontmatter заполнен: `title`, `description` (120–160 символов), `sidebar.order`.
- Каждое число на странице получено настоящим запуском, каждый пример кода запущен.
- После изменений в `src/data/practice/` или `exercises/` запущен `npm run exercises`, и `practice.json` закоммичен.
- `npm run check:content`, `npm run build` и `npm run check:links` проходят.
- В описании сказано, что изменено и почему.

Если вы раньше не работали с pull request, руководство GitHub [о pull request из форка](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork) пошагово объясняет процесс.
