Подписка — это период: она начинается, а потом заканчивается. Задачи про периоды спрашивают, пересекаются ли два из них, когда у клиента был доступ, сколько дней покрыто и сколько подписок было активно одновременно. Код короткий. Ошибки — на границах: период, который заканчивается ровно тогда, когда начинается следующий, период внутри другого, неотсортированный вход.

<Aside type="tip" title="Коротко">
- Периоды полуоткрытые, `[start, end)`: начало входит, конец — нет. Длина — `end - start`.
- Активен в момент `m`: `start <= m < end`.
- Пересечение `[a, b)` и `[c, d)`: `a < d and c < b`. Стык концов — не пересечение.
- Слияние: сортировка по началу, текущий период расширяется через `max(cur_end, end)`, пока следующий начинается не позже его конца, иначе начинается новый.
- Покрытое время — сумма длин слитых периодов. Из-за сортировки это O(n log n).
</Aside>

## Полуоткрытые интервалы

```python
from datetime import datetime

sep = (datetime(2026, 9, 1), datetime(2026, 10, 1))
oct_ = (datetime(2026, 10, 1), datetime(2026, 11, 1))
m = datetime(2026, 10, 1)                     # полночь между двумя месяцами

print(sep[0] <= m < sep[1], oct_[0] <= m < oct_[1])   # False True -- момент только в одном месяце
print(sep[1] - sep[0], oct_[1] - oct_[0])             # 30 days, 0:00:00 31 days, 0:00:00
```

Сентябрь — это `[1 сентября, 1 октября)`. У полуоткрытых (half-open) периодов три полезных свойства:

- **Каждый момент принадлежит ровно одному периоду.** Полночь 1 октября — в октябре, а не в обоих месяцах.
- **Длина — это вычитание.** `end - start` даёт 30 дней для сентября, без `+ 1`.
- **Соседние периоды стыкуются, но не пересекаются.** Продление, которое начинается в момент окончания прошлого периода, — не двойная подписка.

В учебных данных каждая транзакция хранится как `[start_time, end_time)`, и диапазонные типы PostgreSQL по умолчанию тоже `[)`. Если в задаче это не сказано, спросите: *"Is the end of the period included or excluded?"*

## Проверка пересечения

Два периода пересекаются, когда каждый начинается раньше, чем закончился другой. В коде, где `a` и `b` — два периода:

```python
from datetime import date

def d(day):
    return date(2026, 9, day)

def overlaps(a_start, a_end, b_start, b_end):
    return a_start < b_end and b_start < a_end

def overlaps_wrong(a_start, a_end, b_start, b_end):
    return a_start <= b_start < a_end or a_start < b_end <= a_end   # «конец b внутри a»

cases = {
    "apart":      (d(1), d(5), d(10), d(15)),
    "touching":   (d(1), d(10), d(10), d(15)),
    "partial":    (d(1), d(10), d(5), d(15)),
    "a inside b": (d(5), d(6), d(1), d(30)),
}
for name, c in cases.items():
    print(f"{name:<11} {overlaps(*c)!s:<6} {overlaps_wrong(*c)}")
```

| Случай | `overlaps` | `overlaps_wrong` |
|---|---|---|
| apart (врозь) | `False` | `False` |
| touching (стык) | `False` | `False` |
| partial (частично) | `True` | `True` |
| a inside b (a внутри b) | `True` | `False` |

Сравнения строгие (`<`), потому что конец в период не входит: у периодов со стыком 10 сентября нет общего дня. «Неправильная» версия проверяет, попадает ли конец `b` внутрь `a`. Она пропускает случай, когда `a` лежит внутри `b`: тогда ни один конец `b` внутри `a` не находится. Проверка из двух сравнений покрывает все случаи, и её проще проговорить вслух.

Длина пересечения — самый ранний конец минус самое позднее начало, но не меньше нуля:

```python
from datetime import timedelta

def overlap_days(a_start, a_end, b_start, b_end):
    return max(timedelta(0), min(a_end, b_end) - max(a_start, b_start)).days

print(overlap_days(d(1), d(10), d(5), d(15)))    # 5 -- с 5 по 9 сентября
print(overlap_days(d(1), d(10), d(10), d(15)))   # 0 -- стык
print(overlap_days(d(1), d(5), d(10), d(15)))    # 0 -- врозь: без max() было бы -5
```

## Слияние после сортировки по началу

Слияние превращает список периодов, которые могут пересекаться, в список без пересечений. Это ответ на вопрос «когда у клиента был доступ?». После сортировки хватает одного прохода:

1. Отсортировать периоды по началу. Кортежи сортируются по первому элементу, так что достаточно `sorted(periods)`.
2. Держать текущий период. Если следующий начинается не позже текущего конца, расширить конец до `max(current_end, end)`.
3. Иначе есть разрыв: закрыть текущий период и начать новый.

Вот как это идёт для пяти периодов в сентябре, заданных в порядке `[20, 25)`, `[1, 10)`, `[5, 20)`, `[2, 3)`, `[28, 30)`:

| Следующий период (после сортировки) | Шаг | Текущий период | Результат на этот момент |
|---|---|---|---|
| `[1, 10)` | новый | `[1, 10)` | `[1, 10)` |
| `[2, 3)` | расширить | `[1, 10)` | `[1, 10)` |
| `[5, 20)` | расширить | `[1, 20)` | `[1, 20)` |
| `[20, 25)` | расширить | `[1, 25)` | `[1, 25)` |
| `[28, 30)` | новый | `[28, 30)` | `[1, 25)`, `[28, 30)` |

`[20, 25)` стыкуется с `[1, 20)`, и этот цикл их сливает, потому что `start <= current_end`. Для покрытия это неважно: разрыва нет в любом случае. В списке, который читают люди, это может быть важно, поэтому спросите: *"Should periods that touch be merged?"*

Две ошибки встречаются часто, и обе проходят простые примеры:

- **Нет `max()`.** С `current_end = end` период `[2, 3)` внутри `[1, 10)` его укорачивает: для этих двух периодов цикл вернёт `[1, 3)`.
- **Нет сортировки.** На `[20, 25)`, `[1, 10)`, `[5, 20)` в исходном порядке тот же цикл вернёт только `[20, 25)`: каждый следующий период «пересекается» с первым, а его начало не сдвигается.

Сортировка стоит O(n log n), проход — O(n). Сравнение каждой пары периодов — O(n²), и слитого списка оно всё равно не даёт.

## Покрытое время

Покрытое время — сумма длин слитых периодов. В разборе выше это `[1, 25)` плюс `[28, 30)`: 24 + 2 = 26 дней. Пересечения считаются один раз, потому что слитые периоды не пересекаются.

Близкий вопрос-продолжение — наибольшее число периодов, активных одновременно. Обычный ответ — заметающая прямая (sweep line): +1 в каждом начале, −1 в каждом конце, сортировка событий и счётчик по ходу.

```python
def max_active(periods):
    events = []
    for start, end in periods:
        events.append((start, +1))
        events.append((end, -1))
    events.sort()                    # в один момент -1 раньше +1: конец сначала освобождает место
    active = best = 0
    for _, delta in events:
        active += delta
        best = max(best, active)
    return best

periods = [(d(1), d(10)), (d(5), d(20)), (d(10), d(15)), (d(12), d(13))]
print(max_active(periods))                            # 3 -- 12 сентября: [5, 20), [10, 15), [12, 13)
print(max_active([(d(1), d(10)), (d(10), d(15))]))    # 1 -- стыкующиеся периоды не активны вместе
```

Порядок при равном времени следует из полуоткрытости. Если бы начала шли раньше концов в тот же момент, два стыкующихся периода дали бы 2.

## Практика

<Drill id="y-overlap">

Пересекаются, если каждый начинается раньше, чем закончился другой: `a_start < b_end and b_start < a_end`. Строгое `<` — потому что конец не входит: стык 10 сентября — не пересечение. Третья проверка — период внутри другого, тот случай, на котором ломается «конец b внутри a?».

</Drill>

<Drill id="y-merge">

Сортировка по началу и один проход: держим текущий отрезок и расширяем его, пока следующий начинается не позже его конца, иначе прибавляем его длину к сумме и начинаем новый. `max(cur_end, end)` не даёт периоду внутри текущего его укоротить. Третья проверка — разобранный выше пример без `[28, 30)`, в перемешанном порядке: 24 дня. Без `max()` цикл вернёт 22, без сортировки — 5. Пустой список должен дать 0. O(n log n) из-за сортировки.

</Drill>

<Drill id="y-max-active">

Заметающая прямая из раздела выше: +1 на каждом начале, −1 на каждом конце, сортировка, затем текущий счётчик и его максимум. Кортежи сортируются по времени, а потом по второму элементу, поэтому в один и тот же момент `-1` идёт раньше `+1`: конец освобождает место раньше, чем следующее начало его займёт. Это и есть правило полуоткрытого интервала. Во второй проверке три стыкующихся периода идут в обратном порядке. Сортировка только по времени (`key=lambda e: e[0]`) при равенстве сохраняет порядок входа, ставит начало раньше конца и даёт 2. Если для каждого периода считать, сколько периодов с ним пересекается, первая проверка даст 3: `[2, 3)` и `[5, 6)` оба пересекаются с `[1, 10)`, но не друг с другом. O(n log n) из-за сортировки.

</Drill>

```python
# a: [1 ------- 10)
# b:            [10 ------ 15)    стык: общего дня нет
```

Two periods overlap if each one starts before the other one ends."* Для самого загруженного момента ответ — заметающая прямая: *"Plus one at each start, minus one at each end, and ends first when the times are equal."*
</Aside>
