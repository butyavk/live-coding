На некоторых интервью код на Python обращается к той же базе, что и SQL-часть. Эта задача тренирует разделение работы: SQL фильтрует данные и отдаёт короткий результат, Python делает логику, которую неудобно писать на SQL, а параметры попадают в базу безопасно. Задача опирается на страницу [Python и SQL](/python/python-and-sql/) и на фильтры из [Отчётов о выручке](/sql-tasks/revenue-reports/).

<Aside type="tip" title="Как тренироваться">
Соберите решение за три запуска. Сначала только SQL для mer_01, с выводом на экран. Потом цикл поиска серии на списке дат, записанном прямо в коде. Потом обе части вместе — и только тогда «Проверить».

Тесты P11, кроме того, что читает ваш исходный код, обращаются к учебной базе из Python. Для этого нужен свежий Chrome или Edge (WebAssembly JSPI). В других браузерах эти тесты пропускаются с сообщением.
</Aside>

## P11. SQL + Python together: longest sales streak

<Task id="p11" />

<Reveal title="Разбор" try>

**Зачем.** «Лучшая серия дней с продажами». SQL отдаёт короткий список дней, а логику серии проще написать на Python.

**Шаги.**

1. SQL: `SELECT DISTINCT CAST(t.start_time AS DATE)` через `products` к продавцу (merchant), с `NOT is_test`, `revenue_usd > 0`, диапазоном дат и `ORDER BY day`. Параметры — через плейсхолдеры `?`.
2. Python: один проход по отсортированным дням. Если день равен предыдущему + 1, текущая серия растёт, иначе начинается новая. Хранить лучшую серию и её первый день.

**Ловушки.**

- `last_day` входит в диапазон, поэтому в SQL нужно `start_time < last_day + 1 день`: передать `last_day + timedelta(days=1)`.
- Параметры — только через `?`, никогда через f-строки или `+`. Это защищает от SQL-инъекций, и база может переиспользовать план. Это проверяют два теста. Один запускает вашу функцию на соединении, которое записывает каждый запрос, и падает, если id продавца или дата оказались внутри текста SQL. Другой читает ваш исходный код и падает, если f-строка, `+`, `%` или `.format()` собирает строку, похожую на SQL.
- При сериях одной длины остаётся самая ранняя: сравнение строгое, `>`.
- Без продаж ответ — `(0, None)`, поэтому лучшую серию начинать именно с этих значений.

**Проверка.** Для mer_01 с 1 по 29 сентября SQL возвращает 14 дней, а ответ — `(3, date(2026, 9, 21))`: 21, 22 и 23 сентября.

**Стоит сказать.** На большой таблице фильтр и `DISTINCT` остаются в базе: она отдаёт 14 строк, а не все транзакции. Серию можно найти и в SQL приёмом «gaps and islands» — упомяните его, даже если пишете на Python.

**Сложность.** Часть на Python — `O(d)` для `d` дней с продажами. Часть на SQL — одно чтение по диапазону; на большой таблице ему помог бы индекс `(product_id, start_time)`.

**В других редакторах.** В SQLAlchemy то же правило выглядит как именованные параметры: `conn.execute(sa.text("… WHERE p.merchant_id = :mer"), {"mer": merchant_id})`.
